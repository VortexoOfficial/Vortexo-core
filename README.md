Vortexo Core

Vortexo is a non-custodial, zero-knowledge privacy pool for native-asset deposits and withdrawals — the chain's native coin (e.g. ETH on Ethereum, BNB on BNB Chain), not just ETH specifically. Deposit into a fixed-denomination pool behind a commitment, then later withdraw to any address by proving in zero-knowledge that you own an unspent note — without revealing which deposit it came from.

This repository is the core cryptographic and contract layer: the Circom circuits, the Solidity pool contract, the Merkle tree logic, and the generated Groth16 verifier. It does not include deployment scripts, a frontend, or a relayer — those are expected to live in separate repos that consume this core.

How it works

Deposit

Off-chain, generate a random secret and nullifier.
Compute commitment = Poseidon(secret, nullifier, denom).
Call deposit(commitment, denom) sending exactly the native-coin amount for that denomination.
The commitment is inserted as a leaf into that denomination's Merkle tree.

Withdraw

Off-chain, generate a Groth16 proof (via the withdraw circuit) showing you know a secret/nullifier pair for a leaf in the tree — without revealing which leaf.
Call withdraw(...) with the proof, the Merkle root, the nullifierHash, and the target recipient (plus an optional relayer fee).
The contract verifies the proof, checks the nullifier hasn't been spent, and pays out — recipient gets the note value minus the pool fee and relayer fee, if any.

Because withdrawal only requires proving membership in some leaf of the tree, there's no on-chain link between a given deposit and its later withdrawal.

Architecture
File	Purpose
contracts/VortexoFunZK.sol	Main pool contract — deposits, withdrawals, fee handling, ownership, reentrancy guard
contracts/IncrementalMerkleTree.sol	Four independent append-only Merkle trees (depth 20, Poseidon hash, 30-root history), one per denomination
contracts/Verifier.sol	Groth16 verifier auto-generated by snarkJS for the withdraw circuit
circuits/withdraw.circom	Main circuit: recomputes the commitment and nullifier hash, proves Merkle membership, and binds all public signals into the proof
circuits/merkleTree.circom	Reusable Merkle path membership checker (MerkleTreeChecker)
verification_key.json	Groth16 verification key (BN128 curve) matching the compiled circuit — source of truth for regenerating Verifier.sol
Denomination pools

Deposits are grouped into four fixed sizes, each with its own isolated Merkle tree and balance — mixing only happens within a denomination:

Constant	Value (native coin)
DENOM_01	0.1
DENOM_1	1
DENOM_10	10
DENOM_100	100
